# FR-018 — Edit a rental before pickup

- Status: Implemented; scope: Admin, Manager, CustomerService.
- `PUT /api/rentals/{id}` requires all four fields: `vehicleId`, `startTime`, `endTime`, `hasDriver`. Dates are UTC. Returns the updated Rental in the common envelope.
- Only pending/pre_inspection with null started_at may be edited. No-op requests after start are rejected too. Customer, rental type, policy and subscription identity are immutable.
- Actual changes are rejected once a contract is signed, an inspection exists, an assignment is active, any payment attempt exists, or an invoice is no longer unpaid. Release/review operational evidence through its own workflow; editing never silently invalidates it.
- Before creating a PayOS link, checkout reserves the owned invoice atomically under rental then invoice locks and records immutable `checkout_started_at`. Only unpaid invoices can be reserved. Any checkout marker also blocks editing, including when the provider request fails: an external link may already exist. GET invoice remains read-only. Migration 0020 adds the marker idempotently; cancellation does not clear it automatically.
- On first upgrade, migration 0020 also marks existing unpaid invoices, whose old external checkout links were not recorded. Replaying the migration never freezes newly created invoices. Editing legacy unpaid rentals requires an explicit financial reconciliation workflow; no automatic unfreeze is provided.
- Hourly uses the stored hourly price; longterm uses stored monthly price and 30-day rounded-up billing periods. Changing vehicle snapshots the replacement vehicle's current unit price. VAT and deposit retain their original effective ratios from rental monetary snapshots, never current mutable policy rates. Missing/zero price snapshots that cannot be repriced are rejected safely. The unpaid rental invoice is recalculated atomically.
- Subscription edits only reschedule the same vehicle for the same duration, inside the active subscription period; consumed hours remain unchanged. Duration/vehicle changes require cancelling and booking again. Longterm remains self-drive; self-drive requires an approved unexpired license.
- Dispatcher lock, sorted vehicle locks, rental row lock, invoice row locks, and an atomic transaction protect updates. Availability checks and booking exclusion constraints preserve the 60-minute booking buffer and longterm intervals. Active assignments block edits so driver reservations cannot become stale.
- Assignment and replacement transactions re-read and lock the rental after acquiring vehicle locks. A stale Application schedule/vehicle/status snapshot returns 409 RENTAL_CHANGED instead of writing an assignment for the pre-edit terms.
- Errors: 400 invalid or incomplete fields; 404 rental/vehicle not found; 409 RENTAL_NOT_EDITABLE, RENTAL_SIGNED, RENTAL_HAS_INSPECTION, RENTAL_HAS_ASSIGNMENT, RENTAL_FINANCIALLY_COMMITTED, SUBSCRIPTION_EDIT_UNSUPPORTED, SUBSCRIPTION_NOT_VALID, CUSTOMER_LICENSE_NOT_VALID, VEHICLE_UNAVAILABLE or RENTAL_PRICING_UNAVAILABLE.
- Validation covers request completeness, status/start boundaries, snapshot pricing, unpaid invoice synchronization, financial/inspection/assignment guards, overlap rollback, longterm and subscription restrictions.
