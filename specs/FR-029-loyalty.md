## 1. Hiện trạng

Chỉ có cột `customers.loyalty_point INTEGER NOT NULL DEFAULT 0`; **chưa có dòng mã** nào. Acceptance của spec cũ: "immutable ledger, idempotent award" — không thể đạt nếu chỉ cộng dồn trên một cột.

## 3. Quy tắc nghiệp vụ

**Cơ sở tính điểm:** `basis = rentals.total_price` sau quyết toán (tiền thuê + VAT + quá giờ, **không gồm cọc**, **không gồm** phần giảm bằng điểm ở Pha 2), chỉ cho đơn **trực tiếp** (`is_subscription = false`). Đơn theo gói không phát sinh điểm (điểm mua gói là mở rộng: cổng `ILoyaltyAward` đã hỗ trợ `ref_type='subscription_purchase'` nhưng **không nối** — O3).

**Công thức:** `basePoints = floor(basis / 10000)`; `earned = floor(basePoints × multiplier)` với `multiplier` theo hạng tại thời điểm tích (tính từ `lifetimeEarned` **trước** lần tích này).

| Hạng | `lifetimeEarned` | Hệ số |
|---|---|---|
| Member | 0+ | 1.00 |
| Silver | >= 500 | 1.10 |
| Gold | >= 2.000 | 1.25 |
| Platinum | >= 5.000 | 1.50 |

(`lifetimeEarned` = tổng điểm các dòng `type='earn'`, **không** giảm khi quy đổi.) Cấu hình ở `Loyalty` (`ValidateOnStart`): `VndPerPoint`, `Tiers[]`, `Redemption { Enabled=false, PointValueVnd=100, MinPoints=50, StepPoints=10, MaxPercentOfRent=30 }`.

**Idempotent:** mỗi đơn chỉ được tích đúng một lần (`type='earn', ref_type='rental', ref_id=rentalId`); gọi lại không tạo dòng mới và **không** thay đổi số dư. `earned = 0` thì không tạo dòng (ledger không lưu dòng 0 điểm) nhưng ghi log.

**Quy đổi (Pha 2):** điểm trừ khi đặt đơn (dòng `redeem`, `points < 0`); hủy đơn đã quy đổi → dòng `reverse` hoàn lại đúng số điểm (idempotent theo dòng `redeem`). `discount = points × 100đ`, `discount <= 30% × tiền thuê trước VAT`. Việc **áp giảm giá vào giá** nằm trong transaction tạo đơn của BE-12 (cột `rentals.loyalty_discount`, `total_price` giảm tương ứng; hóa đơn lập theo `total_price` mới); BE-27 chỉ cung cấp `ILoyaltyRedemption.QuoteAsync/RedeemAsync(tx, …)`.

## 4. Hợp đồng API

Controller mới `LoyaltyController`. Khách xác định bằng `ICurrentCustomer` (tái dùng nếu đã có).

| Method | Path | Auth | Mô tả |
|---|---|---|---|
| GET | `/api/loyalty/me` | Customer | `{ balance, tier, multiplier, lifetimeEarned, nextTier: {name, pointsNeeded}|null, vndPerPoint, pointValueVnd, redemptionEnabled }` |
| GET | `/api/loyalty/me/transactions?type=&page=&pageSize=` | Customer | Lịch sử (mới nhất trước), phân trang |
| GET | `/api/customers/{id}/loyalty` | Admin, Manager | Tóm tắt + 50 giao dịch gần nhất |
| POST | `/api/customers/{id}/loyalty/adjustments` | Admin | `{ "points": int != 0, "reason": string(5..255), "idempotencyKey": string(<=64) }` — điều chỉnh thủ công |
| GET | `/api/loyalty/redemption-quote?rentAmount=` | Customer | **Pha 2**: `{ maxPoints, maxDiscount, pointValueVnd }` |
| GET | `/api/admin/loyalty/reconciliation` | Admin | Danh sách khách có `drift != 0` (kỳ vọng rỗng) |

Mã lỗi: `INSUFFICIENT_POINTS` (409), `LOYALTY_ADJUSTMENT_DUPLICATE` (200 với dòng đã có — idempotent), `CUSTOMER_NOT_FOUND`, `REDEMPTION_DISABLED`, `REDEEM_OUT_OF_RANGE`.

## 5. Migration `0011` (Pha 1)

Tham chiếu — phải chạy thử trên PostgreSQL 16, có integration test cho từng trigger; file LF.

```sql
CREATE TABLE IF NOT EXISTS customer_loyalty_transactions (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  customer_id     INTEGER NOT NULL,                    -- -> customers.id
  rental_id       INTEGER,                             -- -> rentals.id (nếu có)
  type            VARCHAR(10) NOT NULL,                -- earn | redeem | reverse | adjust
  points          INTEGER NOT NULL,
  reason          VARCHAR(255) NOT NULL,
  ref_type        VARCHAR(30),                         -- rental | loyalty_tx | subscription_purchase
  ref_id          BIGINT,
  idempotency_key VARCHAR(64),
  balance_after   INTEGER NOT NULL DEFAULT 0,          -- trigger điền
  created_by      VARCHAR(255),                        -- email nhân viên cho adjust
  created_at      TIMESTAMP NOT NULL DEFAULT now(),
  CONSTRAINT ck_clt_type CHECK (type IN ('earn','redeem','reverse','adjust')),
  CONSTRAINT ck_clt_points CHECK (
       (type = 'earn'   AND points > 0)
    OR (type = 'redeem' AND points < 0)
    OR (type IN ('reverse','adjust') AND points <> 0))
);
CREATE UNIQUE INDEX IF NOT EXISTS ux_clt_ref ON customer_loyalty_transactions (type, ref_type, ref_id)
  WHERE ref_type IS NOT NULL AND type IN ('earn','redeem','reverse');
CREATE UNIQUE INDEX IF NOT EXISTS ux_clt_idem ON customer_loyalty_transactions (customer_id, idempotency_key)
  WHERE idempotency_key IS NOT NULL;
CREATE INDEX IF NOT EXISTS ix_clt_customer ON customer_loyalty_transactions (customer_id, id DESC);

-- BEFORE: chỉ KHÓA + kiểm tra + tính balance_after (KHÔNG ghi bảng khác)
CREATE OR REPLACE FUNCTION fn_loyalty_before_insert() RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE cur INTEGER;
BEGIN
  SELECT loyalty_point INTO cur FROM customers WHERE id = NEW.customer_id FOR UPDATE;
  IF NOT FOUND THEN RAISE EXCEPTION 'Customer % không tồn tại', NEW.customer_id; END IF;
  IF cur + NEW.points < 0 THEN
    RAISE EXCEPTION 'Số dư điểm không đủ (%/%)', cur, NEW.points USING ERRCODE = '23514';
  END IF;
  NEW.balance_after := cur + NEW.points;
  RETURN NEW;
END $$;
CREATE TRIGGER trg_clt_before_insert BEFORE INSERT ON customer_loyalty_transactions
  FOR EACH ROW EXECUTE FUNCTION fn_loyalty_before_insert();

-- AFTER: cập nhật số dư đệm (chỉ chạy khi dòng THỰC SỰ được chèn)
CREATE OR REPLACE FUNCTION fn_loyalty_after_insert() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  UPDATE customers SET loyalty_point = NEW.balance_after WHERE id = NEW.customer_id;
  RETURN NEW;
END $$;
CREATE TRIGGER trg_clt_after_insert AFTER INSERT ON customer_loyalty_transactions
  FOR EACH ROW EXECUTE FUNCTION fn_loyalty_after_insert();

-- Bất biến
CREATE TRIGGER trg_clt_immutable BEFORE UPDATE OR DELETE ON customer_loyalty_transactions
  FOR EACH ROW EXECUTE FUNCTION fn_immutable_row();           -- hàm tạo ở 0010; nếu chưa có thì tạo ở đây
CREATE TRIGGER trg_clt_no_truncate BEFORE TRUNCATE ON customer_loyalty_transactions
  FOR EACH STATEMENT EXECUTE FUNCTION fn_immutable_row();

ALTER TABLE customers ADD CONSTRAINT ck_customers_loyalty_nonneg CHECK (loyalty_point >= 0);

CREATE OR REPLACE VIEW v_loyalty_reconciliation AS
SELECT c.id AS customer_id, c.loyalty_point AS cached,
       COALESCE(SUM(t.points), 0)::INTEGER AS ledger_sum,
       c.loyalty_point - COALESCE(SUM(t.points), 0)::INTEGER AS drift
  FROM customers c LEFT JOIN customer_loyalty_transactions t ON t.customer_id = c.id
 GROUP BY c.id, c.loyalty_point;

-- Số dư đầu kỳ: tắt trigger BEFORE để không cộng đôi
ALTER TABLE customer_loyalty_transactions DISABLE TRIGGER trg_clt_before_insert;
ALTER TABLE customer_loyalty_transactions DISABLE TRIGGER trg_clt_after_insert;
INSERT INTO customer_loyalty_transactions (customer_id, type, points, reason, balance_after, created_by)
SELECT id, 'adjust', loyalty_point, 'Số dư đầu kỳ (migration 0011)', loyalty_point, 'system'
  FROM customers WHERE loyalty_point > 0;
ALTER TABLE customer_loyalty_transactions ENABLE TRIGGER trg_clt_before_insert;
ALTER TABLE customer_loyalty_transactions ENABLE TRIGGER trg_clt_after_insert;
```

**Cạm bẫy đã tránh có chủ đích:** với `INSERT … ON CONFLICT DO NOTHING`, trigger `BEFORE INSERT` vẫn chạy trước khi biết có xung đột; nếu trigger đó **ghi** `customers`, dòng bị bỏ qua vẫn để lại tác dụng phụ và **cộng đôi điểm**. Vì vậy `BEFORE` chỉ khóa/kiểm tra/tính, còn việc ghi số dư nằm ở `AFTER` (không chạy cho dòng bị bỏ qua). Phải có test chứng minh điều này.

## 6. Kiến trúc & mã nguồn

* **Domain:** `LoyaltyTier`, `LoyaltyCalculator.Earn(basisVnd, lifetimeEarned, options)`, `LoyaltyRedemptionRules` (Pha 2), `LoyaltyOptions` (kiểm tra hợp lệ khi khởi động: ngưỡng tăng dần, hệ số >= 1).
* **Application:** `ILoyaltyService` (`GetSummaryAsync`, `ListAsync`, `AdjustAsync`), `ILoyaltyAward` (`AwardForRentalAsync(tx, rentalId)` — **chạy trong transaction của `complete`** và dùng `ON CONFLICT DO NOTHING`), `ILoyaltyRedemption` (Pha 2), `ILoyaltyReversalOnCancel` (hook tại `cancel`: nếu đơn có dòng `redeem` thì chèn `reverse`).
* **Infrastructure:** `NpgsqlLoyaltyRepository` (SQL thuần, tham số `NpgsqlDbType`, ánh xạ `23514` → `INSUFFICIENT_POINTS`).
* **WebApi:** `LoyaltyController`, DTO, Swagger, message mapping.
* Tích hợp: FR-018 gọi `ILoyaltyAward` ở bước hook (b); lỗi hook rollback `complete`.

## 7. Kiểm thử (tối thiểu)

* **Domain (unit):** công thức ở các biên (basis 9.999/10.000/19.999; nhân hệ số làm tròn xuống); ngưỡng hạng 499/500, 1.999/2.000, 4.999/5.000; `earned = 0`; `LoyaltyOptions` sai bị từ chối.
* **Integration (PostgreSQL thật):** (1) tích điểm khi `complete`; gọi lại 5 lần → đúng 1 dòng, số dư không đổi (**kiểm tra không cộng đôi**); (2) hai `complete` song song → 1 dòng; (3) `UPDATE`/`DELETE`/`TRUNCATE` ledger bị chặn; (4) số dư không âm: điều chỉnh âm vượt số dư → 409; (5) `customers.loyalty_point = SUM(points)` sau chuỗi 200 thao tác ngẫu nhiên có seed cố định (`v_loyalty_reconciliation` rỗng); (6) idempotencyKey của `adjust` trả lại dòng cũ; (7) số dư đầu kỳ không cộng đôi; (8) hạng đổi đúng sau khi vượt ngưỡng; (9) đơn theo gói không tích điểm; (10) hủy đơn có quy đổi → `reverse` đúng một lần (Pha 2).
* **API:** Customer chỉ xem điểm của mình; Admin điều chỉnh; Manager chỉ xem; ẩn danh 401; Swagger; message mapping.

## 9. Câu hỏi mở / giả định

* **O1.** Giá trị quy đổi (100đ/điểm), ngưỡng hạng, hệ số và trần 30% là đề xuất của Claude — chủ nghiệp vụ xác nhận.
* **O2.** Điểm không hết hạn; nếu cần hết hạn theo lô (FIFO) thì thiết kế lại ledger theo lô.
* **O3.** Có tích điểm khi mua gói thuê bao không (cổng đã sẵn, chưa nối)?
* **O4.** Pha 2: cần thêm `rentals.loyalty_discount` và sửa công thức tính giá/hóa đơn — phải có sự đồng ý của Lạc (BE-12) và Phúc (BE-18/19).
